# 1 概述

本报告为资源池化 failover 适配在线 reform 特性的测试总结报告。被测对象为 openGauss 资源池化部署场景下 failover 流程对在线 reform 的适配能力，验证在不同参数配置（默认参数、并行回放参数开到8、极致RTO、按需回放、按需回放+实时构建）和各类故障注入场景下，failover 能够正确触发在线 reform 并完成集群升主恢复，保障高可用能力。同时验证预期升主时间对比旧版本不劣化，以及7*24h长稳运行后 failover 的稳定性。

测试重点包括：

- 默认参数下各类故障触发的 failover 在线 reform 正确性
- 不同回放模式（并行回放、极致RTO、按需回放、按需回放+实时构建）下 failover 在线 reform 适配
- 二次故障场景（升主过程中再次故障）的处理能力
- 预期升主时间对比旧版本不劣化
- 7*24h长稳运行后 failover 稳定性

# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

本轮针对资源池化 failover 适配在线 reform 特性共设计28条有效测试用例并完成执行，覆盖默认参数、并行回放参数开到8、极致RTO、按需回放、按需回放+实时构建五种参数配置下的各类故障场景（stop主节点、kill gaussdb 6次、kill dss 6次、reboot/panic、网络中断/闪断、进程进入T/D/Z状态、主节点ReadOnly、存储网络中断、二次故障等），以及升主时间对比和7*24h长稳后failover稳定性场景。所有用例均通过，测试中未发现缺陷，各参数配置下failover均能正确触发在线reform完成集群升主恢复，预期升主时间对比旧版本不劣化，整体质量良好。

## 3.2 约束说明

- 本特性仅在资源池化部署模式下生效。
- 不同回放模式（并行回放、极致RTO、按需回放、按需回放+实时构建）需通过对应GUC参数配置启用，failover均需适配在线reform流程。
- TPCC压测时长为10min，故障注入在压测过程中执行。
- kill gaussdb/kill dss 连续6次，验证故障反复注入下的failover稳定性。
