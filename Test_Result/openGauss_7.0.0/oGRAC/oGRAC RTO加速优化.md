**Keywords 关键词**：RBP、RBPS、RTO

**Abstract 摘要**：在不改变WAL正确性边界的前提下，引入基于RBP的页镜像供给与恢复窗口能力，通过批量拉页、按需补页、tail replay与verify闭环缩短整体恢复路径，从而优化RTO。

**缩略语清单： **

| 缩略语 | 英文全名                    | 中文解释                                       |
| ------ | --------------------------- | ---------------------------------------------- |
| RBP    | Recovery Buffer Pool        | 内核测页镜像推送与恢复拉页子系统               |
| RBPS   | Recovery Buffer Pool Server | 保存页镜像并对恢复侧提供窗口与读页服务的服务端 |
| RTO    | Recovery Time Objective     | 恢复时间目标                                   |

# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

oGRAC RTO优化特性共计执行39个用例，主要覆盖功能测试、性能测试、可靠性测试和资料测试。功能测试验证RBP新增9个GUC参数、rbps_ctl和cms管理rbps命令、rbps.conf配置验证、rbps缓存数据页；性能测试验证50w tpmc场景下RTO小于10s；可靠性验证0节点和1节点的rbps断连和rbps进程故障恢复；资料验证RBPS加速恢复说明、GUC参数使用介绍和rbps使用说明。用例执行率100%，发现5个有效问题（含1个资料问题），整体质量良好。

## 3.2 约束说明

1、运行期实时分析在USE_RBP、RBP_RT_ANALYSIS均开启、集群为双节点且未启动DBS时生效；不满足条件时自动使用原有恢复期并行分析
2、RBPS以独立进程方式部署，通过cms启停与管理，不依赖数据库实例生命周期自动拉起

3、页镜像发送必须建立在WAL可见的基础上，不能先于redo可见对外暴露页面版本

## 3.3 关键风险和规避措施

无
