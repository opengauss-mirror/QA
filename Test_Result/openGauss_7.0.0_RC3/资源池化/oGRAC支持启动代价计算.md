**Keywords 关键词**：oGRAC，启动代价

**Abstract 摘要**：本报告是对oGRAC支持启动代价处理特性进行测试的结论总结，主要对几种启动代价估算：（1）基表的索引扫描、全表扫描的启动代价（2）三种join连接的启动代价：Nestloop join、Merge join、Hash join（3）limit代价，包括纯limit子句的代价和有offset的代价（4）group by代价，包括sort group、hash group，以及和气象馆的聚合代价（5）排序，对没有limit子句的排序代价。

# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

oGRAC支持启动代价处理特性，共计执行了19个用例，主要覆盖了功能测试。
功能测试主要覆盖了多种表类型的单表全表扫描、索引扫描、join方式nestloop和hash join、单limit使用、带offset的limit、sort group、多列group、结合聚合函数group的启动代价估算。其中hash join场景由于Hint指定代码未合入，组合多种类型多种表join依然走不到hash join，与开发沟通后期合入后重跑hash join用例。merge join暂未实现，后期合入后重跑merge join用例

测试中没有发现问题，整体质量良好。

## 3.2 约束说明

- 不涉及有关distinct的启动代价计算
- group只支持sort group和hash group
- 依赖有列统计信息和执行计划行数正确信息，依赖已实现的几种join
