# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

​        opengauss兼容A库下支持CREATE FORCE VIEW的用法，共计执行40条用例，主要覆盖基础语法验证、异常场景验证、视图依赖基表测试、视图依赖其他对象测试、扩展功能测试以及不同数据库的兼容性测试。第一，基础语法验证。验证了CREATE FORCE VIEW、CREATE OR REPLACE FORCE VIEW等语法在正向场景下能够正常创建强制视图，并通过pg_rewrite系统表验证视图状态（ev_enabled、ev_qual字段）；验证了在基表不存在时使用CREATE FORCE VIEW可成功创建，补齐基表后重解析恢复正常；验证了CREATE VIEW（非FORCE）在基表不存在时合理报错、FORCE关键字位置错误时报语法错误等异常场景。第二，异常场景验证。验证了用户不具备CREATE VIEW权限时合理报错、引用不存在的对象类型时报错、补齐的基表字段结构不一致时报错等异常情况，均符合预期。第三，视图依赖测试。分别测试了强制视图依赖单个基表、依赖两个基表（均不存在/一个存在一个不存在/均存在）的场景，验证了视图间的依赖关系（包括依赖未补齐基表的强制视图、依赖补齐后的强制视图、依赖正常创建的视图、视图间循环依赖），以及强制视图对自定义类型、自定义函数、序列、schema等对象的依赖行为，还包括级联删除基表和视图的边界场景测试。第四，扩展功能测试。覆盖了跨Schema交互（未指定/显式指定基表schema）、重解析GUC隔离（验证重解析过程不影响当前会话的current_schema）、函数和存储过程中调用CREATE FORCE VIEW、事务中创建FORCE VIEW（提交/回滚）、gs_dump导出强制状态视图和已重解析视图的导入导出等扩展场景。第五，兼容性验证。验证了B库、PG库和D库（MSSQL库）均不支持CREATE FORCE VIEW语法，符合仅A兼容库支持的约束。最终测试未发现相关bug，所有40条用例全部通过，测试通过率为100%。
