**Abstract 摘要**：本报告是对D兼容性-DDL语法兼容2 PART2特性进行测试的结论总结，主要对（1）支持nvarchar(max)，max代表无约束。支持nvarchar数据类型，没有给出长度时表示长度1，即nvarchar(1)。（2）支持'< >'操作符，即大于小于符号中间支持包含任意个空格，仍代表不等于的含义。（3）支持DROP TRIGGER trigger_name;语法，不需要加表名，B库已支持。（4）支持sys.identity_columns视图。在D兼容性的约束下表现符合预期。

# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

D兼容性-DDL语法兼容2 PART2特性，共计执行了55个用例，主要覆盖了功能测试、升级测试、兼容性测试、耦合功能测试、资料测试。

功能测试主要覆盖建表指定数据类型nvarchar(max)，数据类型转换，nvarchar(max)边界测试，特殊类型测试，结合事务、存储过程、函数、匿名块、触发器测试，结合分区表、临时表、unlogged表、mot表测试。支持'< >'操作符覆盖从表中查询使用表达式中包含'< >'测试，直接使用，空格数量是否影响，建表使用'< >'，结合事务、存储过程、函数、匿名块、触发器测试。支持DROP TRIGGER trigger_name;语法覆盖直接测试，创建后不加表名删除测试，结合存储过程、函数、匿名块、事务测试。支持sys.identity_columns视图覆盖视图字段测试，视图功能测试，视图相应函数测试，权限测试，异常测试。

升级测试主要覆盖从不带shark插件的RC1版本->shark插件3.0的RC3版本，带shark插件1.0的RC1版本->shark插件3.0的RC3版本，带shark插件2.0的RC2版本->shark插件3.0的RC3版本3个场景进行升级中执行相关业务，回滚中执行相关业务，测试升级和回滚过程正常无报错。

兼容性测试主要针对其他兼容性库进行该特性验证，覆盖A,B,C,PG兼容性，相关不支持语法正确报错，数据库功能正常，无core无宕机。

耦合功能测试包含数据库相关工具功能验证，包含导入导出功能和驱动相关功能验证，在D库执行本特性相关语法，正常导出，同时可以正常导入到带shark插件的D库。使用JDBC和PDBC执行本特性相关语法，功能与gsql一致，无其他功能问题

资料测试针对官网资料进行测试，相关描述正确无歧义，约束准确，示例可执行。

测试中发现1个功能问题，相关问题单正在修改中，整体质量良好。
