**Keywords 关键词**：D兼容性，支持#符号或##符号开头的临时表功能

**Abstract 摘要**：本文档是对openGauss D兼容性下支持D兼容性原生语法#符号（本地临时表）或##符号（全局临时表）开头的临时表功能的测试。

1.实现D兼容模式下，CREATE/ALTER/DROP TABLE时支持创建以#或##开头的临时表，用于实现D兼容的临时表功能。

2.测试本地临时表（#table_name）和全局临时表（##table_name）的创建、删除、修改、数据操作（DML）、索引、约束、视图、触发器、存储过程等场景，以及表名长度限制、可见性（多会话并行）、系统表、用户权限、导入导出、帮助信息等关联功能。

# 1 概述

该测试需求的目的是增强openGauss的D兼容性，实现支持D兼容语法中以#符号开头的本地临时表和以##符号开头的全局临时表功能。本地临时表仅在当前会话中可见，会话退出后自动删除；全局临时表在所有会话中都可见，会话和任务停止后删除。

# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

openGauss的D兼容模式下，实现支持D语法中以#符号（本地临时表）或##符号（全局临时表）开头的临时表功能。共计执行36个用例，主要覆盖创建表（CREATE TABLE、SELECT INTO）、修改表（ALTER TABLE）、删除表（DROP TABLE）等语法，对临时表进行DML操作（增删改查），测试了索引（唯一、btree、hash、全文、部分、表达式、gin、gist）、列字段约束（主键、唯一、btree、check、null、not null，不支持外键）、视图（普通视图，不支持全量/增量物化视图）、触发器（不支持）、存储过程（创建单个/多个临时表、匿名块、动态修改临时表）、系统表、用户权限、帮助信息（\h create table）、导入导出（gs_dump/restore/gsql）等关联场景。结合常用测试场景，通过手工执行用例，发现次要问题5个，问题单主要分布在存储过程相关场景，整体质量良好。

## 3.2 约束说明

1.该功能在openGauss的D兼容模式下使用，要有shark插件。
2.不支持全量/增量物化视图。
3.不支持触发器。
