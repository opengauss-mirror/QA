# 3 版本概要测试结论、关键风险和规避措施

## 3.1 测试结论总结

D兼容性-DDL语法兼容2 PART1特性，共计执行了47个用例，主要覆盖了功能测试、升级测试、兼容性测试、耦合功能测试、资料测试。

功能测试覆盖了建表语句中创建的constraint支持ASC/DESC选项，结合主键约束和唯一约束，与D兼容性聚簇索引等关键字结合使用，唯一约束指定多列，结合多种数据类型，多种表进行测试。数据类型可以使用[]包裹，结合多种数据类型建表，修改表，数据类型转换，多种数据类型作为函数或者存储过程的入参，多种数据类型作为prepare语句的入参，匿名块中变量声明结合多种数据类型。支持ALTER TABLE table_name ADD DEFAULT和支持ALTER TABLE table_name ADD CONSTRAINT语法，直接赋值，结合函数，结合操作符，结合查询表达式，结合变量，不存在的列，错误的表达式进行测试。支持sys.server_principals视图结合视图本身字段，视图的权限，视图的功能进行测试。

升级测试主要覆盖从不带shark插件的RC1版本->shark插件3.0的RC3版本，带shark插件1.0的RC1版本->shark插件3.0的RC3版本，带shark插件2.0的RC2版本->shark插件3.0的RC3版本3个场景进行升级中执行相关业务，回滚中执行相关业务，测试升级和回滚过程正常无报错。

兼容性测试主要针对其他兼容性库进行该特性验证，覆盖A,B,C,PG兼容性，相关不支持语法正确报错，数据库功能正常，无core无宕机。

耦合功能测试包含数据库相关工具功能验证，包含导入导出功能和驱动相关功能验证，在D库执行本特性相关语法，正常导出，同时可以正常导入到带shark插件的D库。使用JDBC和PDBC执行本特性相关语法，功能与gsql一致，无其他功能问题

资料测试针对官网资料进行测试，相关描述正确无歧义，约束准确，示例可执行。

测试中发现2个问题，1个功能问题，1个资料问题，相关问题单正在修改中，整体质量良好。

## 3.2 约束说明

- 在D库中加载shark插件使用
- 当ENABLE_MULTIPLE_NODES开启时，不能使用创建constraint支持ASC/DESC选项。仅当查询计划走index scan时表现与D原生库一致
- 设置参数d_format_behavior_compat_options = 'enable_sbr_identifier'，数据类型可用[]包裹

## 3.3 关键风险和规避措施

无
