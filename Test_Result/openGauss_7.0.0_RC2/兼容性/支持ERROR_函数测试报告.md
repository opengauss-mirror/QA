# 1 概述

本特性是opengauss数据库中，针对D兼容模式下的数据库新增的ERROR相关函数的适配，它允许利用这些函数，对数据库中的报错类型进行各种合法的监控和级别定位等操作。

##  6.1 测试策略回顾

| 编号 | 特性                                                         | 验证策略                                                     | 是否按照测试策略执行 |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------- |
| 1    | ERROR_STATE 函数（标识发生错误的状态代码，范围一般是1~255，通过测试和搜索资料得知，该状态码大部分情况下值都为1，主要用来调试和诊断） | 1.调用对象测试（函数、存储过程、事务、匿名块、触发器等）<br />2.结合try catch调用（try里面、catch里面、try catch外调用、嵌套try catch调用）<br />3.语法校验 | YES                  |
| 2    | ERROR_SEVERITY 函数（获取错误严重级别（通常为1-25的数字））<br />（  0 到 10：信息性错误，通常不会导致事务失败。<br /> 11 到 16：用户错误，通常会中止当前操作或事务。<br /> 17 到 25：系统错误，通常会导致库失效或崩溃。） | 1.调用对象测试（同1）<br />2.结合try catch调用<br />3.语法校验 | YES                  |
| 3    | ERROR_PROCEDURE 函数（获取发生错误的存储过程名）             | 1.调用对象测试（主要是存储过程和函数中0个错误、1个错误、多个错误验证输出报错正常且完整）<br />2.结合try catch调用<br />3.语法校验<br />4.存储过程名称校验（超长、中文、大小写） | YES                  |
| 4    | ERROR_NUMBER 函数（获取数据库特定的错误编号，是一个整数，代表代码中的具体错误，如除零错误编号为33816706） | 1.调用对象测试（同3）<br />2.结合try catch调用<br />3.语法校验 | YES                  |
| 5    | ERROR_MESSAGE函数（获取完整的错误描述信息）                  | 1.调用对象测试（存储过程中额外试验多种不同的错误类型，如1/0、数据不满足表约束、调用其他函数报错、重复执行时候报错等，其他测试项同3）<br />2.结合try catch调用<br />3.语法校验<br />4.输出错误信息验证（输出信息为：中/英文；输出方式为：raise、gms_output、建表存储错误信息） | YES                  |
| 6    | ERROR_LINE 函数（获取错误发生的行号，若是存储过程，从begin开始计算行号，空行也会被计算） | 1.调用对象测试<br />2.结合try catch调用<br />3.语法校验      | YES                  |
| 7    | 兼容性测试                                                   | 分别在A/B/C/PG库中执行如上函数语法，有明显报错，无core无hang | YES                  |
